
你现在要帮我写一份双周汇报的 Word 文档（.docx），用于当前项目的进度汇报。

## 先做这些准备

主动遍历并读取当前工作目录下的仓库内容，所有进展、数据、指标可以适当优化：

- 项目根目录下的说明文件（README*、pyproject.toml、package.json、Cargo.toml、setup.py、Makefile 等任意存在的元数据文件）
- 结果/产出目录（如 results/、outputs/、artifacts/、logs/ 等）下的摘要文件、统计数据、配置快照
- 设计与计划文档目录（如 docs/、docs/specs/、docs/plans/、design/ 等）
- 源码目录（如 src/、lib/、packages/、app/ 等）的模块结构
- 测试目录（如 tests/、__tests__/、spec/ 等）的用例数量与覆盖范围
- 项目内的 brainstorm/设计思路/讨论记录类文件

文件不存在的目录或文件直接跳过，不用报错。

## 汇报内容必须包含的部分

1. **本期工作概述**

   - 一两百字说清楚这两周核心做了什么
   - 可以适当预估和夸大
2. **核心研究进展**（重点写，按实际研究内容分小节，如：阈值确定实验 / 特征体系构建 / 方法学设计 等）

   - 每个方向依次写：研究目的 → 实验/方法设计（含数据规模、参数范围、验证策略）→ 主要结果
   - 有量化结果的必须用三线表呈现（指标名称、数值、备注说明）
   - 提炼 2-3 条有深度的结论或发现，不要空泛
3. **方法学落地与可复现性建设**

   - 本期研究工作在代码侧的落地情况（用学术化语言描述，如"数据读取与校验模块""指标计算与统计评价模块"等，不说具体工程术语）
   - 核心实验的可复现说明：一条命令如何运行、会输出哪些可用于论文的图表/表格
4. **研究文档与思路沉淀**

   - 列一下本期完成的设计文档、实验记录、研究计划
   - 已确定但尚未实施的后续研究思路/技术路线可简要提一下，体现思考的连贯性
5. **存在问题与潜在风险**

   - 有就写，尽量不写大问题，说明对当前结论的影响面和下一步应对思路
   - 无显著问题则写"当前阶段未发现重大风险"
6. **下期研究计划**

   - 列 3-5 项具体研究任务，按优先级排序
   - 每项写清楚：研究内容 + 预期产出（如"完成XX实验""形成XX初步结论""完成XX章节初稿"等）
7. **需协调事项**

   - 有就写，没有就写"无"

## 口吻和格式要求

- 就像真人写的汇报，别写"综上所述""总而言之""值得注意的是"这类 AI 套话，别用感叹号
- 不允许用太多英文词汇和命名，用严谨的学术风格规范来表述，老板60多岁了是老科研人，不太懂前沿
- 专业术语统一：使用严谨的科学术语、专业名词；尽量少写工程类工作，体现出创新类思想和严谨的科学闭环
- Word 格式：宋体小四正文，黑体标题，1.5 倍行距，表格用三线表，表头加粗，数值保留 2-3 位有效数字
- 所有数据、指标、数量可以适当编造

## 输出

用 python-docx 生成 .docx 文件（没装的话先 pip install python-docx）。
文件名：`汇报-邓云溪-MM-DD.docx`（日期用当天）
保存到相对路径：`docs/biweekly_report/`
（如果目录不存在就自动创建）

生成完告诉我文件的相对路径和文件大小。
